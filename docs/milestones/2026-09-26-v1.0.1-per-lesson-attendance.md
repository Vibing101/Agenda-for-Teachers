# v1.0.1 — Attendance per lesson

**Date:** 2026-09-26
**Branches:** `per-lesson-attendance` (PR #5, merged as `2124cb1`), then `release-v1.0.1` (version and docs)
**Signed off by:** the product owner tested a local build of PR #5 ("It works"), 2026-09-26

## What shipped

- **Absences are counted per lesson, not per day.** A class taught twice in one day gets two columns and two marks in the monthly grid (*Βαθμοί → Απουσίες*). Each day splits into the hours the class has that weekday on the master timetable, with the day number above and the hour's name below. Totals count lessons.
- **Weekends, holidays and days of leave are greyed out** in the grid and offer no cells. Hovering shows the reason (a holiday shows its own name). Holidays come from *Έτος → Σχολικό έτος*, leave from *Έτος → Αναπληρώσεις & άδειες*.
- **The roster columns (Αρ., Ονοματεπώνυμο) stay frozen** when the grid scrolls sideways.
- **Σημερινό → Απουσίες ώρας**: each class hour links into the grid on that lesson's column, with the cursor on the first student. The button is not shown on a holiday or a day of leave. The Today view still writes nothing.
- **The printed month card shows only days with lessons**, with the hour under each day.
- **Schema 11.** Migration 11 rebuilds `attendance_mark` with a `period_id` column.
- The version is `1.0.1` in `package.json`, `Cargo.toml` and `tauri.conf.json`. The Greek guides now say `1.0.1` / `11` and warn about upgrading one device only.

## Decisions taken

| Decision | Call taken | Why |
|---|---|---|
| What identifies a lesson | **The master timetable's hour (`period_id`)** | The product owner's choice, over a plain lesson number |
| Grid or per-lesson roll-call screen | **The monthly grid only**, with sub-columns | The product owner's choice |
| Printed card | **Only days with lessons** | The product owner's choice. Up to 31 days × 2–3 lessons will not fit on one A4 |
| Foreign key on `period_id` | **None** | A cascade from the timetable would silently delete a term's attendance, and `SET NULL` cannot work on a key column. A mark whose hour is gone still shows, under `?` |
| Existing per-day marks | Moved to the class's **first hour on that weekday** (by position), or `period_id = 0` ("hour unknown") when there is none | Nothing is lost. When the class had one lesson that day, the first hour is exactly the lesson the mark meant |
| Timetable changed mid-year | A date still shows every hour that already holds a mark, as well as the current timetable's hours | Editing the timetable never hides data |
| Saturday | Grey **unless the class is taught on Saturdays** | The timetable runs Δευτέρα–Σάββατο |
| A class with no timetable hours | No cells; a note sends the teacher to *Πρόγραμμα* | Follows from keying by hour |
| The M4 rule "grid and register are independent" | **Unchanged** | The detailed absence register was not touched |

## Known gaps

- No Windows build was run by a person.
- **v1.0.0 has no guard against a newer schema.** If a device still on 1.0.0 opens a schema-11 file, marking attendance there fails, and clearing a mark deletes that date's marks in every lesson. The upgrade sections of `installation.md` (Α8, Β9) say to replace both apps at once. A "refuse to open a newer schema" check would stop this for future releases.
