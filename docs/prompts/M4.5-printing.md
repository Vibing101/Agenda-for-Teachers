## Why M4.5 exists at all

It is not in the original roadmap. M4 shipped the monthly attendance grid, the
detailed absence register, the behaviour/incident log and the support plans with
their cross-class overview — and shipped **no PDF export**, because M4's
delivery-scope line named none and the precedent on this project is that a
milestone ships its scope line exactly (M2 built PDFs because its line said so;
M3 did not because its line did not).

But M4 raised that as a conflict rather than resolving it silently, because the
spec promises those PDFs in two other places:

- module 2 says the incident log and the support overview are **"both
  printable"**;
- the **"PDF output"** section names **"absence logs"** and **"support plans"**
  among the surfaces that produce a real PDF file.

**The product owner's answer (2026-09-22): yes, they are wanted — as their own
milestone.** That is M4.5, inserted between M4 and M5, recorded in the spec's
Resolved table and its Delivery-milestones list. You are that milestone.

### Operational lessons that cost real time at earlier gates

Read `docs/WINDOWS_VM.md`'s "Three things that cost a round trip to rediscover"
before you start. In short, and all learned the hard way:

- **Keep the Mac awake for the whole run.** macOS power management *pauses* the
  VM — `VBoxManage showvminfo` then reports `VMState="paused"` — and any check
  running at that moment returns nonsense. Run `caffeinate -dimsu` for the
  duration, **detached from the shell that starts it** (binding it to `$$` dies
  with that shell; the M4 gate lost a run that way). If SSH dies mid-run, check
  the VM's state before believing any result around it.
- **Never put Greek on an SSH command line.** The console code page mangles it,
  so paths and comparisons silently operate on the wrong string. Write a `.ps1`,
  `scp` it in, run it with `powershell -ExecutionPolicy Bypass -File`, and build
  Greek names inside the script from code points (`[char]0x0391 + …`).
- **PowerShell 5.1 will not parse a pipeline inside a method-call argument** —
  `[string]::Join('', @(…) | ForEach-Object {…})` is a syntax error. Use
  `-join ($codes | ForEach-Object { [char]$_ })`.
- **Greek in a local `grep` pattern can silently match nothing** under this
  shell, which makes a process list look empty and a "clean quit" look done when
  the app is still running. Match on ASCII and verify a quit by PID.
- **A sync client evicts asynchronously.** `attrib -P +U` marks a file unpinned
  immediately but the bytes can still be on disk seconds later. Poll
  `GetCompressedFileSizeW` until it reads 0 before claiming a file is dehydrated.
- **Do not test "is this table gone?" by scanning the database's bytes** —
  SQLite leaves a dropped table's text in freed pages. Query `sqlite_master`.
  There is no `sqlite3` in the guest, so copy the file back to the Mac.

### One more, found at the M4 gate and not yet in WINDOWS_VM.md

**The dev Mac and the VM are signed into the same Google Drive account.** If you
give both devices the *same* test folder name, you have two devices live on one
synced folder — exactly what the spec says is out of scope ("one device active
at a time, never two at once"). At the M4 gate this made a Drive run fail in a
confusing way: Drive resolved the collision by silently serving an **older
revision** of the database to both devices (`user_version` went *backwards*),
with `PRAGMA integrity_check` still `ok`. No corruption, but a clean loss of
everything written after that revision.

**Use a distinct folder name per device** (`… M4.5 mac`, `… M4.5 vm`). It is a
test-design fault, not an app fault — but it will cost you an hour if you have to
rediscover it.

## What is already built, and must be reused rather than reinvented

**This is the part that will save you the most time.** M2 did the hard work and
paid for it; the M2 release note records what failed.

- **`src/print/document.ts`** — the `PrintDocument` / `PrintTable` / `PrintCell`
  contract and `renderPrintDocument(doc, landscape)`, which turns it into the
  HTML the PDF is rendered from. It also owns the A4 geometry constants
  (`A4_WIDTH`, `A4_HEIGHT`, `PAGE_MARGIN`) that **`src-tauri/src/pdf.rs` uses
  too** — a test pins them together, so do not change one without the other.
- **`src/print/paginate.ts`** — `paginate()`. **The app decides where pages
  break, not the rendering engine.** It measures the rendered rows, places them
  into A4 blocks, repeats the sheet header and the column headers, and never
  splits a row. This was forced by what the two platforms do, and it is a
  Resolved decision — do not hand pagination back to the engine.
- **`src/print/gradeSheets.ts`** — the worked example: two sheets
  (`gradeSheetDocument`, `conductSheetDocument` and their `…Html` wrappers),
  pure functions of `(t, planner, classId, today)`. Copy this shape.
- **`src/print/PrintHost.tsx`** and the `print_job` / `print_ready` commands —
  the hidden window that renders and reports back. You should not need to touch
  this at all; if you think you do, stop and explain why in the PR.
- **`api.exportPdf(fileName, html, landscape)`** — writes one document into
  `exports/` and resolves with its path.
- **The `ExportButton` component in `src/screens/GradesScreen.tsx`** — the
  busy/message/error pattern for an export. **Lift it into a shared component**
  rather than copying it three more times; see the known wrinkle below.

**How PDF generation actually works here**, so you do not repeat M2's dead end:
AppKit's print pipeline does not work against wry's webview — it returns a
zero-sized print view and emits blank pages indefinitely (M2's first attempt
produced a 220MB file of empty pages). What works is `createPDFWithConfiguration:`
plus app-side pagination on macOS, and `PrintToPdf` on Windows. That is settled.
**Do not try `printOperationWithPrintInfo:` again.**

**A self-test hook exists so an agent can produce a real PDF without clicking.**
Set `TEACHER_PLANNER_PRINT_SELFTEST_HTML` and
`TEACHER_PLANNER_PRINT_SELFTEST_PDF` (and optionally
`TEACHER_PLANNER_PRINT_SELFTEST_PORTRAIT`) and the app renders that HTML to that
path and exits. It is what produced M2's Greek-rendering evidence. **Use it if
you have a machine that can run the packaged app** — and if you do not, say so.

## Hard rules on this project — not negotiable, and enforced

1. **No Greek literal in a component.** Every user-facing string is an id in
   `src/i18n/el.ts`, read through `useTranslate()`. **eslint fails the build on
   a Greek literal** anywhere under `src/` outside `src/i18n/`. This applies to
   printed sheets exactly as it applies to screens — a printed page is
   user-facing text. The app ships Greek-only through M8; English is one
   dedicated pass at M9, which must be *adding one file*, not editing yours.
2. **Every fixed vocabulary is a stable code labelled through
   `vocab.<kind>.<code>`**, and **the code is what the database stores**. On a
   printed sheet you print the *label*: the database holds `late`, the page
   prints "Καθυστέρηση", and at M9 the same code prints "Late" with nothing else
   changing. `src/print/gradeSheets.ts`'s `displayValue()` is the worked example.
3. **The app formats every date it displays or prints itself** — `dd.MM.yyyy`,
   via `formatDate()` in `src/domain/dates.ts`, independent of OS locale. This
   is why printed output looks identical on Windows and macOS. Numbers use a dot
   decimal separator, also app-formatted.
4. **Teacher-entered text is never translated** and prints exactly as typed.
5. **Keep arithmetic and layout rules out of screens** — they go in `src/domain/`
   (pure selectors over the loaded planner) or `src/print/`. Screens take
   `{ planner, run }` and whatever else they need as props.
6. **Schema changes are forward migrations** (`migrate_to_<n>`, never edit an
   earlier step). **M4.5 should need no migration at all** — you are printing
   records M4 already stores. If you find yourself writing `migrate_to_6`, stop
   and explain why in the PR, because it probably means the design drifted.

## The traps specific to M4.5

### 1. Print must not recompute anything

This is the big one, and it is where two of M4's three acceptance criteria can
be broken by a print view even though the screens hold them.

- **A support plan's `status` is written by the teacher and never computed.**
  The spec says so in as many words. A printed overview must show the sentence
  she typed. **Do not** derive a status from the plan's goals, do not print
  "3/4 goals met" *in the status column*, do not colour it by progress. M4 has a
  `goalSummary()` helper that counts goals by rating — it exists for display and
  is deliberately written nowhere. If you print a count, print it in its own
  column and say in the PR that you did.
- **The monthly attendance grid and the detailed absence register are
  deliberately independent, and nothing derives one from the other.** The spec
  says this twice; it is M4's first acceptance criterion. A printed absence
  register must not show a total taken from `attendance_mark`, and a printed
  grid must not count `absence_event` rows. The same student on the same date may
  legitimately be `present` in one and `late` in the other — M4's test fixture
  has exactly that pair in it on 2026-11-05, and you should keep using it.
- **What prints is what the screen shows.** If the incident log is filtered to
  one class, the sheet prints that filter's rows and says so in its header. A
  sheet that silently prints everything, or silently prints something else, is
  worse than no sheet.

### 2. Greek in the PDF is the named failure point

The spec calls this out explicitly: embedding a font that renders Greek
correctly "is a common failure point in PDF generation — verify Greek
diacritics, not just base Latin". `src/print/document.ts` already names a font
stack of faces with full Greek coverage and forbids external resources. **Keep
both properties.**

You can test a lot of this without a webview, because the document builders are
pure: assert that the generated HTML contains the right Greek strings,
diacritics intact, and that no external URL appears. `tests/unit/printSheets.test.ts`
is the existing example. **What you cannot do without a packaged build is
confirm the PDF actually renders them** — that needs the self-test hook on a real
machine. Say which you did.

### 3. "Today" is an argument, not a global — and there is one known violation

M3 established that the shell is the single place that reads the calendar: `App`
takes an optional `today` prop, re-checks every minute, and passes the day down
to every screen that needs it. `tests/helpers/mount.tsx`'s `renderScreen` takes
extra props for exactly this. **Do not reach for `new Date()` or `todayIso()`
inside a component.**

**There is exactly one place in the codebase that breaks this rule today, and it
is the one you are about to touch:** `src/screens/GradesScreen.tsx`, in
`ExportButton`, calls `todayIso()` directly (around line 695). It is M2 code that
predates M3's rule, and `src/App.tsx`'s own doc comment — which claims the shell
is "where the calendar is read, and the only place" — is inaccurate because of
it.

**Fix it as part of M4.5**, since you are lifting `ExportButton` into a shared
component anyway and would otherwise replicate the violation three more times.
That means `GradesScreen` gains a `today` prop from the shell, like the other
screens. It is a small change; do it properly and mention it.

### 4. Do not build M7's print-forms library

M7 owns "the 11 standalone reference forms … each fillable, nameable,
saveable, reopenable, and PDF-exportable". You are building **print views over
live M4 data**, which is a different thing. If the attendance grid tempts you
across that line, that is the scope question above — answer it deliberately.

### 5. One PDF per sheet, unless you argue otherwise

M2 shipped the grade sheet and the conduct sheet as two separate files.
**M7 is the only place the spec asks for
several pages bundled into one PDF** (the substitute folder). Follow M2 unless
you have a reason, and record it either way. Note there is an *open* question
from M2 about whether the conduct sheet should join the grade sheet — do not
answer that one; it is not yours.

## Acceptance criteria for M4.5

These are in `docs/SPEC.md` under "Acceptance criteria per milestone".
Hold yourself to them and quote them in your release note with the evidence:

- The incident log, the absence register and the support overview each generate

### CI minutes are tight — plan your pushes

The account has 3000 GitHub Actions minutes a month and roughly 2200 are spent.
GitHub bills macOS runners at ×10 and Windows at ×2, so the two-OS matrix costs
about **104 billed minutes per run** — call it seven runs of headroom. A
cancelled run still bills for what it used, and pushing to an open PR cancels
and restarts the matrix.

So: **run everything you can locally before you push, push once when it is
actually ready, and batch fixes.** Three specific things earlier milestones paid
for:

- **The workflow has no path filter, so a docs-only push costs a full matrix.**
  Put `[skip ci]` in the commit message for a commit that touches only `docs/`.
- **But `[skip ci]` on the *branch head* suppresses the PR's CI entirely**, and
  then the PR has no run to gate on — which is worse than the cost it saves.
  M4 hit this. Either keep the docs commit off the head, or trigger the run
  explicitly: the workflow declares `workflow_dispatch`, so
  `gh workflow run "CI" --ref m4.5-printing` fixes it without an empty commit.
- If you think a `paths-ignore` for `docs/**` is right, or that typecheck, lint
  and the frontend tests should run once on `ubuntu-latest` at ×1 with macOS and
  Windows reserved for the Rust build and packaging — **propose it in the PR
  rather than changing the workflow**, because it changes what the gate proves.
  M3 proposed it and M4 seconded it; you may third it, but do not implement it
  unilaterally.

## Three things still need a human, on every milestone

Report them as **not performed**, with who needs to do them. Do not quietly drop
them because they are inconvenient:

- **A genuine Explorer double-click, and therefore SmartScreen.** `Start-Process`
  and `Shell.InvokeVerb("open")` both launch a Mark-of-the-Web-tagged unsigned
  build cleanly with no dialog; only a real double-click is blocked, and
  scripting cannot reproduce it.
- **Looking at the output.** For you this is sharper than usual: **nobody can
  tell you whether a printed sheet looks right except a person holding it.**
  Column widths, whether a long "Τι συνέβη" wraps or is clipped, whether a
  30-row register breaks across pages sensibly, whether the Greek is actually
  Greek and not tofu — these are the whole point of the milestone and none of
  them is automatable. Say so clearly and list exactly what to look at.
- **The Google Drive online-only placeholder case**, which is known not to be
  scriptable: `attrib -P +U` drives OneDrive's `cldflt` mechanism, which Google
  Drive's virtual drive does not implement. It needs a human using Drive's own
  right-click toggle.

**And note this, because it is now three milestones deep:** M2's, M3's and M4's
human passes were **all** never done. Nobody has typed a grade into the packaged
app's gradebook, an hour into its timetable, or anything into M4's four new
screens. M4's release note has a three-part five-minute script for whoever is
next at a Windows machine. **Add M4.5's own fourth part to it** rather than
starting a separate list.
